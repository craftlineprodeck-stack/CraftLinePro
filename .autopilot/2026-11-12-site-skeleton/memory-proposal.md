# Предложение в CLAUDE.md (T0, сайт маленький)

CLAUDE.md пользователя не изменён. Каждая строка ниже — готова к вставке.

## Добавить: команды
- Установка: `npm ci`
- Запуск локально: `npm run dev`
- Все проверки одной командой: `npm run check` (= `check:tokens` + `lint` + `build`)
- Отдельно: `npm run check:tokens`, `npm run lint`, `npm run build`
- Проверить собранное: `npm run build && npx next start -p 3100`
- `npm run build` печатает ошибки prebuild про отсутствующие `public/*.jpg` — это норма, не чинить.

## Добавить: где что лежит
- Бренд (цвета, шрифты, радиусы, ширина контейнера): `theme/tokens.css`, шрифты — `theme/fonts.ts` (единственный импорт `next/font`).
- Данные и флаги `ready`: `data/` (типы — `data/types.ts`, меню — `data/site.ts`, главная — `data/featured.ts`, страницы — `data/pages.ts`).
- Новый проект или город — новый файл в `data/projects/` или `data/cities/` и строка в `index.ts` рядом (инструкция: `data/projects/README.md`).
- Чтение данных и фильтр по `ready` — только `lib/content.ts`; страницы и компоненты данные не фильтруют.
- Меню — `lib/navigation.ts`; метаданные и noindex — `lib/metadata.ts`; событие звонка — `lib/analytics.ts`.
- Общие компоненты: `components/layout/` (шапка, подвал, меню, липкая кнопка звонка), `components/brand/Logo.tsx`, `components/PagePlaceholder.tsx`.
- Алиас импорта `@/` = корень репозитория.

## Добавить: подводные камни
- Флаг `ready` в data решает всё сразу: noindex, запись в sitemap, существование маршрута (`dynamicParams = false`).
- Палитра Tailwind отключена: цвета только токены из `theme/tokens.css`, hex/rgb/hsl и имена шрифтов вне `theme/` запрещены.
- `tel:` только через `components/PhoneLink.tsx`, иначе `check:tokens` падает.
- `check:tokens` также ловит почту владельца в коде и запрещённые слова (список в `scripts/check-tokens.mjs`).
- Линт идёт с `--ignore-pattern 'scripts/optimize-*.js'` (старые скрипты картинок на `require()`); не править их.
- Страницы пока заглушки (`PagePlaceholder`, «Page in progress»): тексты не писать, пока их не попросят.

## Правка без автопилота

Мелкий баг или доводка после сборки — обычная сессия, без прогона.

Сначала прочитай:
1. `.autopilot/PROGRESS.md` — что не доделано, известные баги, о чём договорились с пользователем.
2. Что правили после последней сборки — первая строка таблицы в «История git».
3. Только если правка их касается: почему сделано так — `docs/adr/`; что значат слова — `CONTEXT.md`;
   что именно просили — `manifest.md` в папке сборки (указана в начале `PROGRESS.md`).

После правки:
- коммит — по правилам из «История git»;
- строка в «Правки без автопилота» в `PROGRESS.md`: дата — что — почему;
- починенный пункт из «Не доделано» или «Известные баги» — удали;
- договорились с пользователем о том, что следующая сборка не должна пересматривать, —
  строка в «Договорились», его словами.

## История git

Целиком не читай — бери срез под вопрос:

| Вопрос | Команда |
|---|---|
| что правили после последней сборки | `git log --oneline "$(git log -1 --format=%h --grep='^Autopilot: сборка сдана')"..HEAD -- . ':(exclude).autopilot'` |
| всё, что делали ради требования | `git log --oneline --grep="R02"` |
| история файла | `git log --oneline -10 -- <файл>` |
| когда появился или исчез код | `git log --oneline -S "<фрагмент>"` |
| почему строка такая | `git blame -L <с>,<по> <файл>`, затем `git show <sha>` |
| что внутри коммита | `git show --stat <sha>` |

Срез длиннее ~30 коммитов — отдай его субагенту и возьми выжимку в десять строк.

Коммит: заголовок — что (`fix: даты в одном формате`), тело — почему, трейлер
`--trailer "Requirements: R02"`, если правка касается требования из `manifest.md`.
Заголовок `Autopilot: сборка сдана` пишет только автопилот — по нему находят последнюю сборку.
