# Спецификация: CraftLine Decking v2 — каркас сайта (этап 1)

## Задача
Владелец хочет новый сайт CraftLine Decking, который собирается по этапам. На этапе 1 нужен каркас, в который потом без переделки вёрстки ложатся тексты, проекты, города и отзывы. В каркасе бренд меняется за час, а в поиск не попадает ничего недоделанного.

## Решение
Новый сайт на Next.js App Router + TypeScript + Tailwind v4 в ветке `stage-1-skeleton` от `v2`, сдаётся PR в `v2` (R01, R02). Что появляется:

- **Бренд в одной папке `theme/`** (R03–R06). В `tokens.css` лежат все цвета (Ocean Slate `#1E2B32`, Warm Amber `#D49A44`, нейтральные), семейства шрифтов, скругления, ширина контейнера и отступы. Стандартная палитра Tailwind отключена (`--color-*: initial`), поэтому цвет вне токенов в коде просто не сработает. `fonts.ts` только подключает Inter (текст) и Oswald (заголовки) через `next/font` и отдаёт их в нейтральных переменных `--font-body` / `--font-display`. Временный логотип — один компонент: SVG из нескольких ромбов друг над другом и надпись CRAFTLINE / DECKING, цвета берутся из токенов. Проверка `npm run check:tokens` (A01 → R04) находит hex/rgb/hsl-цвета и имена шрифтов вне `theme/`.
- **Чистка старого** (R07–R09). Удалены `app/components/HomePage.tsx`, `LazyMap.tsx` и старые цвета из `globals.css`. `not-found` переведён на токены. Из `next.config.ts` убран readdy.ai. Файлы в `public/` не меняются вообще.
- **Данные в `data/`** (R10–R16), типы в `data/types.ts`:
  - `site.ts`: название, юрлицо, телефон (вид для показа и формат tel), Instagram, адрес сайта и **структура меню** (`nav`: упорядоченный список пунктов About · Services ▾ · Resources ▾ · Service Areas · Projects · Before & After · Contact; у Services дети берутся из услуг, у Resources — из страниц `deck-materials` и `blog`). Почты нет.
  - `services/`: 6 услуг в порядке владельца. У каждой slug = адрес страницы, название, короткая подпись для меню, `ready`.
  - `cities/`: 5 городов запуска — Fair Oaks, Orangevale, Citrus Heights (East Sacramento County), Folsom (Folsom & El Dorado Hills), Granite Bay (Placer County). У каждого регион и `ready`. Плюс список 4 регионов в порядке из CLAUDE.md.
  - `projects/` и `reviews/`: пустые списки и формат. Проект и отзыв связаны с городом **полем `city`** (slug города). Проект: `city`, услуга, материал, площадь (sq ft), дни, «до», «что сделали», отделка, фото с alt и подписью, пары до/после как ссылки на фото этого же проекта, `ready`. Отзыв: автор, `city`, услуга/проект, текст, дата, источник.
  - `featured.ts`: акцент (`repair-restoration` сейчас, `building` с весны) и порядок показа избранных проектов и отзывов — пока пустой.
  - `pages.ts`: служебные страницы (главная, материалы, до/после, города, проекты, отзывы, о нас, контакты, Deck Academy, блог, privacy) с `ready`.
  - Сейчас все `ready` выключены: готового текста ещё нет.
- **Все маршруты из таблицы как заглушки** (R17–R19). На странице только H1 с названием страницы и метка «Page in progress» — никакого текста про компанию. Неготовая страница получает `robots: noindex, nofollow`. Как только в данных включают `ready`, noindex снимается сам.
- **Флаг `ready` управляет показом** (R20–R22, R28). `/areas/[city]` строится только для городов с `ready`, остальные отдают 404. В `/areas` показываются только карточки готовых городов, сгруппированные по 4 регионам; пустые регионы скрыты; когда готовых городов нет, видна метка-заглушка. `/projects/[slug]` работает так же по готовым проектам. Строка городов в подвале показывает только готовые города и скрыта, когда их нет. В sitemap попадают только готовые страницы, услуги, города и проекты: сейчас он пустой, и так задумано.
- **robots.ts** не закрывает `/_next/` (R23).
- **Шапка, меню, подвал** (R24–R28):
  - Меню: About · Services ▾ (6 услуг по порядку) · Resources ▾ (Materials; Blog только при `ready` у блога) · Service Areas · Projects · Before & After · Contact · кнопка телефона.
  - Выпадающие списки открываются с клавиатуры и мышью.
  - На телефоне меню прячется в кнопку, панель закрывается по Escape и при переходе по ссылке.
  - Внизу экрана на телефоне висит кнопка звонка; на десктопе её нет.
  - Подвал: услуги по порядку, строка готовых городов, телефон, Instagram, CraftLine LLC, ссылка на Privacy.
- **Телефон через один компонент `PhoneLink`** (R29): все `tel:` ссылки сайта идут через него. Внутри один no-op `trackCall(location)` в `lib/analytics.ts` — сюда позже вешается GA4-событие `call`.
- **Проверка** (R30, R31): `npm run build`, `npm run lint`, `npm run check:tokens` зелёные, осмотр на ширине 375 px, затем push ветки, PR в `v2` и ссылка на превью Netlify. **PR сливает владелец**, сам я его не сливаю.
- **Правила CLAUDE.md в коде** (R32, R33i): CLAUDE.md не меняется. В коде нет слов licensed / cedar / Carmichael, почта не выводится, нет старых названий компании.

- **Журнал автопилота** — `.autopilot/` (требования, спецификация, таски) коммитится вместе с каркасом.

## Решения по реализации
- Код вне `app/` лежит в корне: `theme/`, `data/`, `lib/`, `components/`. `app/` — только маршруты. Alias `@/` уже смотрит в корень.
- Tailwind v4: `app/globals.css` = `@import "tailwindcss"` + `@import "../theme/tokens.css"`. Токены объявлены через `@theme`, поэтому классы вроде `bg-slate`, `text-amber`, `font-display` генерируются сами.
- Статическая генерация: `generateStaticParams` + `dynamicParams = false` у динамических маршрутов.
- Меню собирается функцией из данных (услуги + страницы), а не руками в шапке. Поэтому новая услуга или готовый блог появляются в меню без правки вёрстки.
- Метаданные страницы — одна функция `pageMetadata()`. Она ставит title, canonical и noindex по флагу `ready`.
- `prebuild` (старый скрипт картинок) оставлен: он ничего не пишет, потому что исходников `.jpg` нет. Убирается на этапе 2.
- Без новых зависимостей. Иконки, если нужны, — встроенный SVG или уже установленный `react-icons`.
