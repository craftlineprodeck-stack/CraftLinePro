## 2. Стек и процесс
- Next.js (App Router, статическая генерация), Tailwind + дизайн-токены в одном файле (замена бренда за час).
- Репозиторий: github.com/craftlineprodeck-stack/CraftLinePro. Хостинг **Netlify** (деплой из main, превью на каждый PR, проект sage-kataifi-d9bfbb). Claude GitHub App установлен — Claude пушит ветки и открывает PR. Сборки, где меняются только *.md и .claude/, Netlify пропускает (netlify.toml, PR #5).
- Домен зарегистрирован в Squarespace, но **DNS управляется в Netlify** (nameservers dns1–4.p02.nsone.net). DNS-записи добавлять только в Netlify → DNS. Кнопку «Use Squarespace nameservers» не нажимать — сайт перестанет открываться.
- Работа: Claude Code → ветка → PR → превью Netlify → Merge. Новый сайт собирается в ветке `v2`.
- **Правило владельца (04.11):** до начала сборки сайта в GitHub ничего не заливаем. Все решения и правки копим в проекте (этот бриф + `claude/CLAUDE.md (draft).md`); финальная версия CLAUDE.md уходит в репозиторий одним PR перед стартом сборки `v2`.
- CLAUDE.md в корне репозитория: бренд, услуги, города, запреты. Актуальный черновик — `claude/CLAUDE.md (draft).md` в проекте (в репозитории пока версия PR #4).
- Контент в файлах данных (услуги, города, проекты, отзывы) — новый проект/город = новый файл.
- Форма: своя функция Netlify + письмо на почту, загрузка до 5 фото; антиспам — Cloudflare Turnstile + honeypot + фильтр скорости + серверная проверка + лимит по IP. Email открытым текстом не показывать.
- Аналитика: Search Console (подтверждён, ресурс «Домен», 2 TXT-записи в Netlify — не удалять) + GA4 (события «звонок», «форма»), UTM на ссылке из GBP; подменные номера только на сайте.
- **Источник клиента (требование владельца 12.11):** по каждой заявке и звонку видно, откуда пришёл клиент и сколько принесла каждая реклама. Состав: UTM на всех своих ссылках (GBP, Yelp, Instagram, реклама); форма незаметно сохраняет первый источник визита (utm, gclid, сайт-источник, страница входа) и пишет его в письмо о заявке; GA4 + конверсии Google Ads (форма и звонок); LSA считает свои заявки в своём кабинете; кнопки звонка — один общий компонент. Подменные номера (call tracking, напр. CallRail) — _ждёт решения_ (платный сервис), до этого звонки считаются по нажатию кнопки. Делается на этапе форм, до запуска рекламы.
- Без баннера куки; страница Privacy Policy обязательна.

## 3a. Иерархия услуг (решение владельца 04.11) — образец подачи: SIA Builds
Порядок в меню, списках услуг и футере:
1. **Строительство и ребилд деков** — главный фокус подрядчика. Материалы: Redwood, композит (**Trex №1, TimberTech №2**), экзотический хардвуд (Ипе и др.).
2. **Ремонт** — замена доски, работа с фреймом (лаги, балки, опоры), перестил доски на существующем каркасе.
3. **Реставрация и рефинишинг** — две отдельные категории:
   - **Redwood** — №1 по объёму;
   - **Ипе и хардвуд** — премиальная линия, с объяснением тонкостей работы с плотной древесиной (Ипе, Cumaru, Tigerwood, Garapa, бамбук Dasso; замена досок, обслуживание маслом).
   - Композит не реставрируется — такой категории нет.
4. **Дополнительно:** перила (Redwood, композит, алюминий), лестницы, перголы. Заборы — второстепенно, для своих клиентов.

**Акцент по времени:** до марта–апреля 2027 главная (первый экран, избранные проекты, отзывы) делает упор на **ремонт и реставрацию** — это сильная сторона и основная масса кейсов. Порядок в меню при этом не меняется. С марта–апреля, по мере появления строительных кейсов, акцент смещается на строительство. Переключается в данных (порядок «избранного»), без редизайна.

Кейсы для строительства сейчас: новый Redwood дек (Folsom), ребилд spa-дека из Ипе (Fair Oaks), лестницы (Folsom, Auburn), замена досок/перил/лестниц на Trex (Rancho Cordova). Новых Trex/TimberTech-строек пока нет — каждую стройку 2027 снимать с первого дня (разметка → опоры → каркас → настил → готово). Фото материалов Trex/TimberTech — только с подписью «product photo».
